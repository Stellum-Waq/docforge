## 本版改动

### 图片转 Excel：识别质量

评测台：`tools/table_eval.py`（10 个用例，含拍照、密集大表、合并单元格、宽表）

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 平均单元格准确率 | 65.1% | **99.6%** |
| 最差用例 | 41.7% | **96.3%** |
| 显示格式保真 | 55.6% | **99.6%** |

修掉的四个成因：

- **本地行高检测永远返回 0 个框**。RapidOCR 在纯检测模式下返回的是裸多边形，
  而代码按 `(box, text, score)` 解析，解析出的"文本"其实是坐标点，
  随后被当非法数据丢弃。行高是切片决策的**唯一**输入 ——
  它一直是 0，等于整套自适应切片都在用猜的数字做决定。断链不报错，只安静做坏结果。
- **小图被判成"字太小"而被竖着切成两半**：一张 784×354 的干净表格被切成 2 块，
  表格从中间劈开、右半边整列丢失、一张表变成两张工作表。
  而这张图的缩放比例其实是 1.00 —— 模型根本不会缩小它。
- **跨切片的表格片段被当成多张表**：表头相同、行不同、接缝还重复。
- **数值格式丢失**：`1,250` 变成 `1250`（千分位没了）；
  `¥128,600.00` 转换失败留成文本，那一列无法求和。
  现在值与显示格式一起给 —— 既能参与计算，显示又与原件一致。

### 收益最大的一项：裁掉四周空白

模型按**整图**决定缩放比例，所以空白边距会直接吃掉正文分辨率：

```
远距大图切片   2400×3200 → 901×1080    缩放 0.41 → 1.00   (去掉 87% 空白)
手机拍A4      3000×4000 → 1340×1824   缩放 0.33 → 0.71   (去掉 80% 空白)
```

裁边后这两张图不再被缩放，文字以原生分辨率送进模型，准确率从 55% / 96% 变成 96% / 100%。

### 不再静默交付不确定的结果

实测缩放后字形低于约 12px 时，**同一张图重复识别三次的准确率可以是
10% / 83% / 79%**（波动 72 个百分点）—— 模型不是"稍微差一点"，
而是有时编、有时蒙对（把"复印纸"读成"密封圈"）。

现在这种情况会明确提醒，并写进任务摘要与日志：

```
1 张表 · 27 行 · ⚠ 字号偏小（缩放后字形约 13px，低于可靠的 15px），
识别结果可能不准确甚至出现编造内容 —— 建议把表格拍得更近、更清晰后重试
```

之前这类提醒**只存在于内部对象里**，被动作层丢弃了 —— 用户看到的是绿色的"成功"，
根本不会去复查。任务显示成功但数据是错的，比任务失败糟糕得多。

## 已知限制

- 字号过小时模型会编造内容且结果不稳定（见上）。此时的正确做法是重拍，
  程序会如实提醒。
- 云端 OCR 需要自备 DeepSeek API Key（在设置里填写）；
  默认的本地离线引擎完全免费、文件不出本机，精度略低。
- PDF 加密 / 解密 / 权限设置未实现。
- 未安装 Office 且未安装 LibreOffice 时，Excel / PPT 转 PDF 不可用。
- 仅在 Windows 上验证过。

# 文枢 DocForge 0.1.2

> 办公文件转换与处理中枢 · 本地优先（Local-First）· Windows 桌面

**这一版修好一个会让「图片转 Excel」静默交付空结果的缺陷。**
如果你用 0.1.0 / 0.1.1 遇到过"任务显示成功、Excel 却一个字都没有"，
就是这个原因 —— 请换用本版。

## 本版修了什么

### 现象

一张手机整屏截图（1264×2800 的人员名单表）跑两次都显示"成功"，
但 Excel 里一个字都没有，界面上写着"（未识别到文字）"、平均置信度 0.0%。

### 根因：输出预算被模型的"思考"吃光了

`deepseek-flash` 是**推理模型**：先"思考"再作答，而
**思考 token 也算在 `max_tokens` 里**。表格模式要求严格 JSON 结构，
模型思考得特别久。抓到的原始响应：

```
finish_reason = length
completion_tokens: 8192
completion_tokens_details: {'reasoning_tokens': 8192}   ← 全部被思考吃掉
content 长度 = 0 字符
```

同一张图的思考开销对照：

| 模式 | 思考 tokens | 8192 预算够不够 |
|---|---|---|
| 纯文字 | **240** | 够（6 秒出结果） |
| 表格（强制 JSON） | **7284 ~ 10885** | **被吃光，一个字都没留给回答** |

而代码把"空内容"当成正常返回，一路降级到空结果 —— 用户看到绿色的"成功"，
根本不会想到要去重拍或换个模式。

### 修复

- **默认输出预算 8192 → 32768。** 关键是：**预算是"天花板"，不是"花费"** ——
  模型答完就停。实测把上限从 16384 提到 32768，实际输出仍然只有约 12900 tokens，
  费用一分没多；但给低了会直接把结果毁掉。
- **显式处理 `finish_reason == "length"`**：翻倍预算重试（到 65536 为止），
  仍然截断就**报错**，绝不返回空内容。
- **空内容一律报错**，不再静默降级成"这张图没有内容"。
- 顺带修掉一条**误报**：界面上"字号偏小、结果可能不准"的警告是假的
  （同一次识别的结果完全正确）。原因是"检测框高度 → 字形高度"的换算系数
  按表格样本标定成了 0.6，对行距宽松的手机截图会系统性低估。
  误报会消耗用户对警告的信任，所以只在真正危险时才响。
- "已裁掉四周空白"不再每张图都写进任务摘要，只在裁掉 ≥15% 时提示 ——
  它本来是个成功的优化，不该把真正的警告挤掉。

### 效果

| 指标 | 0.1.0 | 0.1.2 |
|---|---|---|
| 平均单元格准确率（11 个用例） | 65.1% | **99.9%** |
| 最差用例 | 41.7% | **98.9%** |
| 显示格式保真 | 55.6% | **99.9%** |

上面那张实际截图现在能正确抽出 **64 行 × 9 列**，表头
`区队 / 班 / 人数 / 姓名 / 房间号 / 备注` 与内容均正确。

## 0.1.1 相比 0.1.0 的改进（同样包含在本版中）

- **本地行高检测永远返回 0 个框**：RapidOCR 在纯检测模式下返回裸多边形，
  而代码按三元组解析，解析出的"文本"是坐标点、随后被当非法数据丢弃。
  行高是切片决策的唯一输入 —— 它一直是 0，等于整套自适应切片都在瞎猜。
- **小图被判成"字太小"而被竖着切成两半**：表格从中间劈开、右半边整列丢失。
- **跨切片的表格片段被当成多张表**：表头相同、行不同、接缝重复。
- **数值格式丢失**：`1,250` 变 `1250`；`¥128,600.00` 留成文本无法求和。
  现在值与显示格式一起给 —— 能计算，显示也和原件一致。
- **裁掉四周空白**：模型按整图决定缩放比例，空白边距会吃掉正文分辨率。
  `2400×3200 → 901×1080`、`3000×4000 → 1340×1824` 后不再被缩放。

## 已知限制

- 字号过小时模型会编造内容且结果不稳定（实测同一张图三次可以是
  10% / 83% / 79%）。此时程序会明确提醒重拍，不会把不确定的结果当成功交付。
- 云端 OCR 需要自备 DeepSeek API Key（在设置里填写）；
  默认的本地离线引擎完全免费、文件不出本机，精度略低。
- PDF 加密 / 解密 / 权限设置未实现。
- 未安装 Office 且未安装 LibreOffice 时，Excel / PPT 转 PDF 不可用。
- 仅在 Windows 上验证过。

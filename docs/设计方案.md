# 文枢 DocForge — 办公文件转换与处理工具 · 设计方案

> 版本 v1.0 · 面向 Windows 桌面 · 本地优先（Local-First）
> 代号 `docforge`，中文名「文枢」（文之枢纽，可随时更名）

## 0. 环境侦察结论（决定了架构取舍）

在动手设计前先实地探测了目标机器，结论直接影响技术选型：

| 项目 | 实测结果 | 对设计的影响 |
|---|---|---|
| Node.js | v24.14.0 | 满足 Electron / Vite 7 要求 |
| pnpm | 11.21.0 | 用作 monorepo 包管理器 |
| Python | 3.11.0 + pip 26.0.1 | 文档处理核心语言，版本健康 |
| Git | 已安装 | 版本管理就绪 |
| Rust / cargo | **未安装** | Tauri 需额外装 ~1.5GB 工具链 + 长编译，**Electron 更务实** |
| Microsoft Office | **Office 2021 家庭和学生版，Word COM 实测可用（v16.0）** | 🎯 **重大利好**：Word/Excel/PPT → PDF 可走 COM，保真度最高的路径本地就有 |
| LibreOffice | 未安装 | 作为"无 Office 环境的可选兜底引擎"，不强制依赖 |
| PDFgear 2.1.14 | 已安装 | 存在同类工具，说明用户对此类需求真实 |
| 磁盘空间 | C: 51.2 GB / D: 65.2 GB 可用 | 充裕，可容纳 Electron + Python 运行时 |
| DEEPSEEK_API_KEY | 环境变量未设置 | 需在应用内做设置页 + 加密存储 |

**核心结论**：不要选"纯 Python 重写一切"或"纯 Node 硬啃文档格式"，而是
**Electron 负责界面与系统集成 + Python 负责文档处理内核 + 可插拔引擎注册表按优先级择优**。

### C. PDF 水印（对应需求 4）

- **文字水印**：内容、中文字体、字号、颜色、透明度、旋转角度、九宫格/自定义坐标、**平铺（密度 + 错位排布）**
- **图片水印**：Logo 上传、缩放、透明度、旋转、平铺
- **动态变量**：`{page}` `{pages}` `{date}` `{time}` `{filename}` `{user}` `{dept}`
- **页面条件**：页范围、奇偶页、跳过首页/尾页、仅指定书签章节
- **双层水印**：背景水印 + 前景水印叠加
- **元数据水印**：写入 Title/Author/Subject/Keywords（不可见但可溯源）
- **溯源水印（进阶）**：每份文件嵌唯一 ID（微偏移点阵），可反查泄露源
- **加密保护**：设置密码、限制打印/复制/编辑
- **实时预览**：PDF.js 渲染 + Canvas 叠加水印图层，所见即所得
- **批量**：多 PDF 统一水印 / 每文件独立参数 / 模板保存复用

### D. 照片水印（对应需求 5）

- 文字水印 / 图片 Logo 水印
- 位置：九宫格快捷位 + **画布上自由拖拽定位**
- **平铺防盗图水印**：网格间距、角度、透明度
- **智能适配**：水印尺寸按原图比例自动缩放，小图不糊、大图不飘
- **EXIF 方向自动校正后再打水印**（避免横竖颠倒，这是常见坑）
- 保留 / 剥离 EXIF（隐私）；描边、阴影、羽化提升可读性
- **批量**：按文件名 / 日期 / EXIF / 序号生成水印文本，支持"每张唯一"
- 输出：覆盖原件（二次确认）/ 另存目录 / 转 PNG/WebP/JPG（质量可调）

### E. 批量处理（对应需求 6）

- **统一任务模型**：所有功能都是 Job → Task → Step，共用一套队列
- **并发控制**：可调 worker 数；CPU 密集走进程池，IO/API 型走异步
- **进度体系**：总进度 + 单文件进度 + 速度 + 剩余时间估算 + 实时日志流
- **任务控制**：暂停 / 恢复 / 取消 / 失败重试 / 跳过已存在
- 拖入文件夹自动递归展开，可选保留目录结构
- **结果表**：文件、状态、耗时、输出路径、错误详情、一键定位到文件夹
- **冲突策略**：覆盖 / 自动重命名 / 跳过 / 逐个询问
- **预设（Preset）**：一组参数存为"配方"，一键套用到新批次
- **流水线（Pipeline）**：多步骤串链，如 `PDF → OCR → 表格抽取 → Excel → 加水印 → 压缩`
- **监听文件夹**：丢进监控目录自动处理
- **任务历史**：可回放（保存 recipe + 日志）
- 定时任务（可选）

### F. 文件导入方式（对应需求 7）

- **全局拖拽**：窗口任意位置拖入 → 全屏动效 overlay，实时显示文件数/类型/总大小
- **拖入即智能推荐**：自动识别文件类型并高亮推荐可用任务
- 打开文件 / 多选 / **打开文件夹（递归）**
- **剪贴板粘贴**（Ctrl+V 粘图片 / 文件 / 路径列表）

- 最近文件 / 收藏夹 / 拖入即用

- **"发送到"菜单** + 命令行参数直启
- 从 Excel/CSV 导入文件清单批量处理

### G. OCR 双引擎（对应需求 8）

#### G1. 云端：DeepSeek Vision（已核实官方 API）

| 规格 | 值 |
|---|---|
| 模型 | **`deepseek-flash`**（唯一支持 Vision 的模型；`deepseek-v4-pro` **不支持**视觉） |
| 接口 | OpenAI 兼容 `POST https://api.deepseek.com/chat/completions` |
| 图片传法 | ① Base64 `data:` URL（最简）② 公网 URL ③ Files API `file_id`（≤64MiB，可复用） |
| 支持格式 | JPEG / PNG / GIF / WebP（按**内容**嗅探，不看扩展名） |
| 控制参数 | `image_url.detail` = `low`(压到512×512) / `high` / `original` / `auto` |
| 请求上限 | body 48 MiB；单图 32 MiB(base64/URL)；单请求 ≤600 张图 |
| 图片尺寸 | 单边 ≤8192px（≥15 张图时降到 4096px） |
| 结构化输出 | `response_format: {"type":"json_object"}`（需 prompt 含 "json" 字样） |
| 上下文 | 1M tokens，最大输出 384K |
| 价格 | 输入 $0.15–0.30 / 1M（缓存命中 $0.003–0.006），输出 $0.6–1.2 / 1M，**低峰半价** |

> ⚠️ **关键工程风险（必须处理）**：官方在推理前会把图片缩放到"约 1300×1300 等效像素"，
> **单图上限 1024 tokens**。这对版面稀疏的图片足够，但**密集小字文档会糊、会丢字**。
> → 因此必须实现 **自动切片 OCR（Adaptive Tiling）**：
> 1. 先用本地 OCR / OpenCV 做版面分析，定位文本行与表格区域
> 2. 按语义区块（而非机械网格）切图，切块间保留 10–15% 重叠
> 3. 每块独立送 DeepSeek 识别（可复数并发，注意限流）
> 4. 按坐标回贴，用文本相似度 + 位置邻近度做**重叠区去重**
> 5. 全局重排（阅读顺序：分栏 → 单栏，竖排 → 横排）
>
> 这一层是"能不能真正可用"的分水岭，也是本工具相对普通 API 封装的核心壁垒。

#### G2. 本地：离线 OCR（保留本地部署选项）

| 方案 | 特点 | 定位 |
|---|---|---|
| **RapidOCR (ONNXRuntime)** | 纯 ONNX、无 PyTorch 依赖、CPU 可跑、模型约 15MB、启动快、中文效果好 | **默认本地引擎** |
| PaddleOCR / PP-StructureV3 | 表格结构 + 版面分析最强，但依赖重（paddlepaddle） | 按需下载的"增强包" |
| Umi-OCR 对接 | 若用户已装 Umi-OCR，走其 HTTP API | 可选外部引擎 |
| DeepSeek-OCR（自部署） | 3B 模型，需 GPU + vLLM，效果强 | 进阶：给有显卡的用户开"私有化高精度"档 |

#### G3. 引擎抽象与路由

```
OcrEngine (统一接口)
  └─ recognize(image, options) -> OcrResult { blocks[], tables[], text, confidence, bbox }
       ├─ DeepSeekVisionEngine   (云端，切片 + JSON Mode + 缓存 + 用量统计)
       ├─ RapidOcrEngine         (本地，默认)
       ├─ PaddleOcrEngine        (本地增强，可选下载)
       ├─ UmiOcrEngine           (外部，可选)
       └─ LocalDeepSeekOcrEngine (自部署，可选)
```

- **混合模式（推荐默认）**：本地做版面/表格线检测 → 语义切片 → 云端识别 → 合并
  （精度接近纯云端，token 成本显著下降）
- **自动降级**：云端失败/超时 → 本地兜底；断网 → 自动切本地
- **隐私策略**：默认纯本地；启用云端时明确提示"此文件将上传"；支持"含敏感关键词强制本地"
- **成本控制**：结果缓存（`文件哈希 + 参数哈希 + prompt 版本` → 结果落 SQLite），重复文件**零重算零计费**；实时用量与费用面板；单任务预算上限熔断

### 2.4 引擎路由表（设计的核心价值点）

| 转换任务 | 首选（最高保真） | 次选 | 兜底（永远可用） |
|---|---|---|---|
| docx → pdf | **Word COM** ✅ 本机可用 | LibreOffice | docx→HTML→Chromium `printToPDF` |
| xlsx → pdf | **Excel COM** ✅ | LibreOffice | openpyxl→HTML→printToPDF |
| pptx → pdf | **PowerPoint COM** ✅ | LibreOffice | — |
| pdf → docx | `pdf2docx` | OCR 重建 | Word COM 打开另存 |
| pdf 水印/合并/拆分/压缩 | PyMuPDF | pikepdf | — |
| 图片水印/格式转换 | Pillow + OpenCV | — | — |
| OCR | DeepSeek Vision（切片） | RapidOCR | PaddleOCR |

> **COM 引擎工程要点**（血泪坑，必须内建）：
> - 启动时探测 Office 可用性，不可用则自动降级，**绝不硬依赖**
> - COM 是 STA 单线程 → 必须放**专用单线程 worker 进程**，禁止并发调用
> - Word 进程卡死是常态 → 每个任务包**看门狗超时**，超时 `taskkill` 并重试
> - 每次用完显式 `Quit()` + `ReleaseComObject`，防止 WINWORD.EXE 残留堆积

### 2.5 UI 视觉语言（科技风 · 高级动感）

**色彩**
- 深空底色 `#05070D`，层叠面板 `#0B0F1A` / `#111726`
- 极光渐变主色：青 `#22D3EE` → 紫 `#A855F7` → 品红 `#F0ABFC`
- 状态色：成功 `#34D399` / 警告 `#FBBF24` / 失败 `#FB7185` / 运行 `#38BDF8`

**材质**
- 玻璃拟态卡片：`backdrop-blur(20px)` + 1px 渐变描边 + 内发光
- 噪点纹理 + 网格地平线背景 + 扫描线动效
- 发光边缘、数字滚动、进度环

**动效**
- 页面切换：View Transitions API / Motion `layoutId` 共享元素
- 任务运行时：数据流粒子沿路径流动、进度环呼吸光晕
- 微交互：磁吸按钮、光标跟随光晕、hover 3D 倾斜
- 拖拽时：全屏 overlay + 涟漪扩散 + 文件计数弹跳

**性能纪律**
- 动效只用 `transform` / `opacity`（走合成层，不触发重排）
- 尊重 `prefers-reduced-motion`
- 帧率掉到 60fps 以下自动降级特效
- 粒子背景用轻量 Canvas 自研，**不引入 three.js**（省 ~600KB）

**布局**
- 无边框窗口 + 自绘标题栏 + 窗口控制按钮
- 左侧图标导航栏（可折叠）+ 主工作区 + 底部任务中心抽屉
- **命令面板 Ctrl+K**（毛玻璃 + 模糊搜索 + 键盘导航）

## 4. 已识别的关键风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| **DeepSeek Vision 单图 1024 token 上限导致密集小字丢失** | OCR 准确率不达预期（致命） | 自适应切片 + 重叠去重 + 本地版面分析辅助（G1 已详述） |
| Word COM 进程残留/卡死 | 系统变慢、任务假死 | 专用单线程 worker + 看门狗超时 kill + 退出清理 |
| 目标机器可能无 Office | 转换保真度骤降 | 三级降级路由（COM → LibreOffice → 渲染兜底） |
| `pdf2docx` 对复杂版面还原有限 | PDF→Word 排版错乱 | 明示"文字型 PDF 效果最佳"；提供"纯文本模式"与 OCR 重建模式 |
| Python 打包体积/启动慢 | 用户体验差 | onedir 模式 + 延迟加载重依赖 + 启动画面 |
| API Key 泄露 | 安全问题 | `safeStorage`(DPAPI) 加密 + 本地服务 Token + 仅绑 127.0.0.1 |
| API 费用失控 | 用户成本 | 结果缓存 + 预算熔断 + 实时用量面板 + 低峰时段提示 |

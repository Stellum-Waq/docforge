## 4. 过程中遇到的问题与解决（值得记录，避免重踩）

| 问题 | 根因 | 解决方案 |
|---|---|---|
| `electron.exe` 不存在 | pnpm 11 默认拦截依赖的 postinstall 脚本 | `pnpm-workspace.yaml` 的 `allowBuilds` 放行 electron（esbuild/@swc/core 关掉，其平台二进制由 optionalDependencies 下发） |
| pnpm postinstall `spawn EPERM` | 受限环境禁止子进程管道 stdio | 直接用 `node` 运行 electron 的 `install.js`（stdio 继承自 shell） |
| Electron 下载 `EPERM mkdir %LOCALAPPDATA%\electron` | 下载缓存目录在工作区外 | 设 `electron_config_cache` 指向工作区内目录 |
| `python -m venv` 缺 pip | ensurepip 阶段瞬时失败 | 手动补跑 `python -m venv/.venv/Scripts/python.exe -m ensurepip --upgrade` |
| pip 卡死空转 20+ 分钟 | 阿里云 PyPI 镜像个别 wheel 下载停滞 | 换清华 TUNA 源，并**拆成小批次**安装（单批 5–30 秒） |
| pip 报 `invalid cp936 characters` | `pip.ini` 含中文注释，pip 按系统 locale(cp936) 解码 | pip.ini 改为**纯 ASCII**（已在文件内注明约束） |
| 内核因 `%APPDATA%` 不可写而崩溃 | 数据目录未做可用性兜底 | `config.py` 增加逐级降级：目标目录 → 临时目录 → 工作区 `.docforge-data`，并记录降级原因 |
| 主进程找不到 core 包 | `repoRoot` 路径少算一层 | 修正为向上一级 4 层（`out/main` → 仓库根） |
| PyMuPDF 1.28 弃用 `fitz` 别名 | 上游 API 变更 | 探测同时检查 `pymupdf` 与 `fitz`，兼容新旧版本 |
